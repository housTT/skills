`tt-project`:

- a scalar delivery.push_checks, after_push or push_exclude_paths (true, 5) is reported by config_problems, refused by config_set, and a scalar push_exclude_paths refuses pushes to the push branch
- task_update resources ends only a wait on a resource the task no longer lists; probe, start_after/start_when and other waits stay (a compound probe keeps its other steps)
- delivery.after_push also runs after ordinary and detached ttp push to the push branch (not --own), with a durable receipt the daemon turns into an event and, on failure, timeout or kill, an after_push_failed alert; the push stands; a detached push runs it after its outcome is written and its locks are let go; batches keep their own
- charter grants reconciled against the delivery config, model-free; grant parser reads only a plain repo list on one line; a partly set-back grant is never re-applied; grants docstring reflow
- blocker sweep replaces a first-seen entry that items() no longer uses (a requeue or run since it, unobserved by the sweep), so a later update cannot reset the age to the update time
- a task pinned to a Codex model or effort is checked before its run starts: the runner asks `codex app-server` (thread/start, ephemeral, no turn) which model and effort the session resolves with the run's own overrides, records them in run.json and the run note (session), and on a mismatch refuses the run before launch ($0, not waste) and blocks the task without spending an attempt; unpinned tasks and other providers are unchanged, and a check that cannot answer lets the run go ahead, recorded as unverified
