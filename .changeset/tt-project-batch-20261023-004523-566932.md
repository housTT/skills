`tt-project`:

- daemon log gives a kept worktree's reason once per holder task, not on each of its status changes, and no cache line for a worktree removed in the same pass
- blocker sweep carries holds only an open ask can lift (HELD BY OPEN ASK); a budget kind change no longer brings forward a sweep of only held items
- a review whose daemon pre-review checks failed on its tests goes straight to a fix and re-review, with no reviewer run
- worker, reviewer and other non-coordinator runs write the prompt cache at budget.worker_cache_ttl (5m by default)
- worker and reviewer prompt asks for batched reads (every range a step needs in one call, parallel independent reads), not one narrow read per call
- a lock-probe wait's note names who holds each lock now (pid, alive), not the holders its hand-off saw
- a charter_update or user-rule memory_add refused for quoting a relayer's context returns the named message's own words (verbatim, cut at 600 chars), so the next turn can quote them; the next turn's digest shows a relay rejection's quote-back whole, through its cut marker, instead of cutting it at 500 chars
